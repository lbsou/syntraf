# Lab de robustesse SYNTRAF + migration Python 3.14 — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrer SYNTRAF vers Python 3.14 puis livrer un lab Docker local (InfluxDB + serveur + 4 clients) pilotable par `lab/labctl.py`, avec injection de pannes et scénarios pytest S0–S9.

**Architecture:** Une image unique `syntraf-lab` (Python 3.14 + iperf3 compilé) sert au serveur et aux clients ; le code du dépôt est monté en lecture seule puis copié par conteneur. `labctl.py` (stdlib) appelle la CLI `docker` ; sa logique vit dans le paquet `lab/lablib/`. Les scénarios tournent sur l'hôte dans un venv `lab/.venv` et observent via l'API HTTP d'InfluxDB et `docker exec`.

**Tech Stack:** Docker Desktop (WSL2), Docker Compose, Python 3.14 (image et hôte), iperf3 (esnet ou fork davidBar-On), InfluxDB 2.7, pytest, PowerShell 7.

**Spec:** `docs/superpowers/specs/2026-11-20-lab-chaos-design.md`

## Global Constraints

- Branche : `lab-chaos`. Ne pas toucher aux fichiers non suivis existants (`venv*/`, `crypto/`, `log/`, `proc/`, `fake_data/`, `*.txt` d'état…).
- Python : `python:3.14-slim` dans l'image ; Python 3.14 de l'hôte (`py -3.14`) pour `lab/.venv`.
- `labctl.py` et `lab/lablib/` : bibliothèque standard uniquement. pytest seulement dans `lab/.venv`.
- Aucune injection de panne sur l'hôte ou la VM WSL : uniquement `docker exec` dans les conteneurs du lab, `docker network (dis)connect`, `docker pause/unpause/restart` sur les conteneurs du lab.
- Ne jamais modifier `.wslconfig` ni les autres conteneurs Docker Desktop.
- Budget RAM (`mem_limit`) : influxdb 400m, server 256m, c1–c4 128m chacun, grafana 200m (profil `viz` seulement).
- Réseau `syntraf_lab` 172.30.0.0/24 : influxdb .10, server .20, c1 .31, c2 .32, c3 .33, c4 .34, grafana .40.
- Projet compose `syntraf-lab` ; conteneurs `syntraf-lab-<service>` ; services `influxdb`, `server`, `c1`…`c4`, `grafana`.
- UID SYNTRAF des clients : `LAB_C1`…`LAB_C4`. `LAB_C1`, `LAB_C2` en IP fixe dans `server.toml` ; `LAB_C3`, `LAB_C4` en `IP_ADDRESS = "0.0.0.0"`.
- MESH_GROUP unique `LAB` : `BANDWIDTH = "100K"`, `DSCP = "0"`, `PACKET_SIZE = "218"`, `INTERVAL = "1"` → 12 flux. `WATCHDOG_CHECK_RATE = "2"`.
- Délai de reprise accepté : `2·I + W + 10 s` = **14 s**.
- Ports hôte liés à `127.0.0.1` uniquement : InfluxDB 18086, webui 18080.
- Conteneurs : `restart: "no"`, `init: true`, `cap_add: [NET_ADMIN]` (server, c1–c4), `TZ=UTC`.
- Secrets du lab : valeurs factices fixes dans `lab/config/lab.env`, jamais réutilisées ailleurs.
- Migration Python : compatibilité seulement ; aucune modification de la logique de reconnexion, du pilotage d'iperf3 ou de la détection de panne.
- Fichiers `*.sh` du lab en fin de ligne LF (sinon le shebang casse dans le conteneur).

## Review Focus

1. **Interface renommée après `docker network connect`** : après une coupure `disconnect`, l'interface peut ne plus s'appeler `eth0` ; `tc`/`iptables` doivent viser l'interface qui porte l'IP 172.30.0.x, résolue à chaque appel → test `test_degrade_after_reconnect_targets_lab_interface` (Task 4).
2. **Rétablissement idempotent** : `heal` sur un nœud sain, ou deux `degrade` successifs, ne doivent ni échouer ni empiler des qdiscs → tests `test_heal_twice_is_noop` et `test_degrade_twice_replaces` (Task 4).
3. **Scénario interrompu** (Ctrl+C, exception) : aucune panne ne doit rester active ; `status` doit montrer toute panne résiduelle et `down` la retirer → test `test_fixture_heals_on_failure` (Task 6) et `test_status_reports_active_faults` (Task 4).
4. **Docker Desktop arrêté au lancement du raccourci** : `start-lab.ps1` attend le moteur jusqu'à 3 min puis affiche un message clair → test manuel scripté `Test-DockerWait` (Task 5).
5. **Fuseau horaire** : `tzlocal` dans un conteneur slim sans `tzdata` peut planter ou décaler les horodatages ; les points InfluxDB doivent être à l'heure UTC réelle (±2 s) → test `test_points_are_utc_now` (Task 3).

  - Fonctions pures : `faults.netem_cmds(iface: str, delay_ms=0, jitter_ms=0, loss_pct=0.0, rate: str | None = None, to_ip: str | None = None) -> list[list[str]]` ; `faults.drop_cmds(to_ip: str | None = None) -> list[list[str]]` ; `faults.heal_cmds(iface: str) -> list[list[str]]`.
  - Actions : `faults.lab_iface(service) -> str` (interface portant l'IP 172.30.0.x, via `ip -o -4 addr`) ; `faults.degrade(service, **netem)` ; `faults.cut(service, mode: Literal["drop","disconnect","pause"], to: str | None = None)` ; `faults.heal(service)` ; `faults.heal_all()` ; `faults.kill_iperf(service, signal="KILL")` ; `faults.restart(service)` ; `faults.flap(service, mode, off_s, on_s, count)` ; `faults.active(service) -> list[str]` (descriptions lisibles : qdisc netem présent, règles DROP, réseau absent, en pause).
  - CLI : `degrade <svc> [--delay MS] [--jitter MS] [--loss PCT] [--rate R] [--to SVC]`, `cut <svc> --mode {drop,disconnect,pause} [--to SVC] [--for S]`, `heal [<svc>|--all]`, `flap <svc> --mode M --off S --on S --count N`, `kill-iperf <svc> [--signal S]`, `restart <svc>`. `status` affiche `faults.active` pour chaque service ; `down` appelle `heal_all()` avant `compose down`.

Règles : `degrade` utilise `tc qdisc replace` (jamais `add`) ; avec `--to`, qdisc racine `prio` + netem sur une bande + filtre `u32 match ip dst <ip>/32`. `drop` insère des règles `iptables` INPUT/OUTPUT marquées `-m comment --comment syntraf-lab` ; `heal` supprime uniquement ces règles, ignore l'absence de qdisc, reconnecte au réseau avec l'IP d'origine (`docker network connect --ip`) et dépause si nécessaire. `--for S` : coupe, attend S s, rétablit (y compris sur Ctrl+C).
